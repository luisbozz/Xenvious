# AGENTS.md

Guidance for AI coding agents (and humans in a hurry) working on Xenvious.
The full documentation is in [`docs/wiki/`](docs/wiki/Home.md); this file is
the short version with the rules that matter most.

## What this is

Xenvious is a Windows WPF app (.NET Framework 4.8, C# 9, classic `.csproj`
with `packages.config`) that attaches to a running GTA V process and edits the
Content Creator's job data in memory. It supports two game editions,
**Legacy** (`GTA5.exe`) and **Enhanced** (`GTA5_Enhanced.exe`), whose
addresses all differ.

It reads and writes **script globals** and **script locals**, and patches the
creator scripts' **bytecode** at runtime. Build-specific data is generated by a
separate Python tool, ysc-global-updater, and embedded into the exe.

## Environment limits

- Building and running needs **Windows** with Visual Studio 2022 / Build Tools
  (.NET desktop workload). On Linux, macOS or WSL you cannot build, run or
  test; say so instead of claiming a build passed.
- GitHub Actions builds every pull request
  (`.github/workflows/build.yml`). Push your branch and read that result
  instead of guessing; green only means it compiles.
- The memory library [mry](https://github.com/luisbozz/mry) is a separate
  repository, referenced as
  `..\..\mry\mry\bin\x64\Release\mry.dll` (from `Xenvious/Xenvious.csproj`).
- Nothing can be verified without the game running. Testers restart GTA
  before each test (injected bytecode stays in memory otherwise) and close
  Xenvious before rebuilding (the exe is locked). There are no automated
  tests. State clearly what you checked (read the code, built it, tested in
  game on which edition) and what you did not.

## Build

```bat
nuget restore Xenvious.sln
msbuild Xenvious.sln /p:Configuration=Release /p:Platform=x64
```

When bumping a NuGet package, update `Xenvious/packages.config` **and** the
`HintPath` / `Import` / `Error` lines in `Xenvious/Xenvious.csproj` together.

## Map of the code

| Path | Purpose |
|---|---|
| `Xenvious/MainWindow.xaml(.cs)` | The single window and its shared state |
| `Xenvious/MainWindow/MainWindow.<Page>.cs` | Partial class files, one per page or concern |
| `Xenvious/Creator Classes/` | Game logic without UI: `CreatorMap` (rebuild, map backup), `PropMover`, `PreciseTemplates`, `ScrPatchesRunner`, `ScrProgramScanner`, `AdvancedPlacement/` |
| `Xenvious/GTA.cs` | `GTA.Offsets.Editor.*` static offset fields, pointer scans, script thread lookup |
| `Xenvious/Global.cs`, `Functions.cs` | Reading/writing globals, bit helpers, misc utilities |
| `Xenvious/GameVariant.cs` | Detects Legacy vs Enhanced |
| `Xenvious/Helper Classes/OffsetLoader.cs`, `IniText.cs`, `AobCache.cs` | Loads `offsets.ini`, parses decompiler notation, caches pattern hits |
| `Xenvious/OfflineData/<legacy|enhanced>/` | `offsets.ini`, `scrpatches.json` per edition (embedded resources) |
| `Xenvious/OfflineData/*.json` | Props, vehicles, weapons, actors (shared by both editions) |
| `Xenvious/JSON/` | Rockstar job JSON model (`job_json.cs`) |
| `Xenvious/Translation/Translation.cs` | UI texts in six languages |
| `Xenvious/Controls/`, `ViewModels/` | Reusable controls; MVVM for advanced placement |

## Rules

### Game memory

- Go through `new Global(index)` for globals and the helpers in
  `MainWindow.CreatorLocals.cs` for locals. Do not hardcode addresses or
  global indices in code; they belong in `offsets.ini`.
- Check `MainWindow.m.IsProcOpen` before any read or write.
- An array element is `base + index * NEXT + field`. Strides come from the
  `*_NEXT` keys, not from the `/*170*/` comment, which the parser discards.
  Array fields are loaded with `add = 1` (the slot before element 0 is the
  array size).
- `IniText` returns `0`/`""` for a **missing key** without an error, and keys
  are case-insensitive. Guard against `0` before writing.
- Bit helpers in `Functions.cs` (`checkbinary`, `writebinary`) use **1-based**
  bit indices.
- Never mix editions. Edition-specific data only comes through
  `OfflineData` / `OffsetLoader` for `GameVariant.Current`.
- Only the creator you are in has its script loaded. Never read or compare
  another creator's locals.
- Never overwrite an array's size slot (the slot before element 0).
- After bulk writes to job data, the creator must rebuild
  (`CreatorMap`) to show them. Rebuild is only verified for Race, LTS and
  Capture.

### Offsets and patches

- Add a new offset to **both** `legacy/offsets.ini` and `enhanced/offsets.ini`
  in decompiler notation (`Global_N.f_M[i /*S*/].f_K`), add the field in
  `GTA.cs`, load it in `OffsetLoader.Load()`.
- Do not edit `offsets.ini` or `scrpatches.json` values by guesswork. They are
  generated by ysc-global-updater from decompiled scripts; a wrong value
  writes into unrelated game memory.
- Script patch patterns must match exactly once in their script.
- The injected custom functions must be active whenever a patch that calls
  them is active, or GTA crashes.
- AOB patterns: keep them RIP-relative (`48 8B 05 ? ? ? ?`), handle a miss
  (`IntPtr.Zero`), and when one breaks try the other edition's pattern first.
- Keep `OfflineData` files as embedded resources; do not change their build
  action or load them from disk.

### Code and UI

- Put new logic in `Creator Classes/` (static classes are the norm), new page
  code in a new `MainWindow/MainWindow.<Page>.cs` partial with a one-line
  comment at the top saying what it covers.
- Every new UI text gets a key in **all six** dictionaries in
  `Translation.cs` (`ger`, `eng`, `ru`, `pl`, `fr`, `zh_cn`). XAML binds with
  `{Binding Translation[key], FallbackValue=...}`.
- From background threads update the UI with `Dispatcher.BeginInvoke`,
  never `Invoke` (this deadlocked startup once).
- Do not steal focus from the game; use the in-app dialog
  (`MainWindow.Dialog.cs`).
- The UI thread culture is `de-DE`. Parse and format data with
  `CultureInfo.InvariantCulture`.
- Comments explain why (what the game does, what breaks otherwise). Remove
  dead code instead of commenting it out.
- Match the surrounding style: four spaces, braces on their own lines,
  `PascalCase` members.
- The **Online Enabler** (`OnlineEnable.cs`, `MainWindow.OnlineEnabler.cs`)
  downloads `online_enabler.dll` and its checksum and injects the DLL into GTA.
  It is **switched off** (`OnlineEnable.Available = false`) until it has a new
  source; the xenvious.com backend it used is offline.
- Four values in `%AppData%\Xenvious\config.ini` (kill values, menu switcher
  presets, global and local freeze lists) are JSON stored as `b64:` + Base64
  (`Helper Classes/ConfigText.cs`), because the ini API is ANSI. `AES/` only
  reads the AES-encrypted form older versions wrote.

### Git

- Conventional Commits with a scope: `feat(copyjob): ...`,
  `fix(offsets): ...`, `refactor(ui): ...`. English, under ~72 characters,
  one concern per commit.
- Never commit secrets, tokens, personal paths or local editor settings
  (`.vscode/settings.json`, `sftp.json`).
- In the PR, say which creator and which edition you tested, on which game
  build, or that you could not test in game.

## Scope

Xenvious is for building and testing creator jobs. Do not add anything aimed
at GTA Online gameplay, anti-cheat bypasses or other players.
